# 只做连续流控，不做熔断状态机与降级

governor 的输出容易被误解为熔断器或限流器的替代品。明确边界：控制动作仅三种——概率丢弃（策略一）、批次调整（策略二）、延迟等待（策略三）；另有只读观测输出（压力指数 S、抑制因子 α、信号快照），观测不是控制。

抑制是连续、概率式的：α 对有限 S 严格小于 1，且探测放行保证深度抑制时仍有小比例真实请求流出，反馈路径永不归零。这与熔断器"全开后仅剩定时探测"是本质差异。

明确的否定清单：

- **不是熔断器**：无全开/半开/全关状态机，无 tripped 状态与恢复阈值。
- **不内置降级**：被抑制的操作以快速失败信号告终（`ErrSuppressed` / `Allowed == false`），返回默认值、兜底缓存等降级响应由业务层构造。
- **不是并发信号量**：不限 in-flight 上限，只调整流出模式。
- **不是重试引擎**：策略三是延迟执行（延迟而不丢弃），不是失败后的退避重试。

理由：desc.md 的控制论模型是连续反馈调节，状态机是另一种工具，混入会破坏 α 的连续语义与探测保证；降级策略依赖业务语义，库保持单职责。业务需要熔断语义时，可基于暴露的 S/α 在业务层自行构建。
